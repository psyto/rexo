# Rexo — Product Requirements Document

**Version:** 0.1  
**Status:** Draft for MVP  
**Working name:** Rexo

## 1. Product thesis

生成 AI 時代に価値があるのは、コピー可能な一文のプロンプトではなく、結果を出すまでに積み上がった判断、ツール利用、修正、評価の連鎖である。Rexo は、その連鎖を秘密のまま `Skill Capsule` に変換し、再利用時に原著者へ報酬が戻る場所を作る。

## 2. Problem

- AI を使う制作者は、成果の出るワークフローを蓄積しても、成果物以外の価値を持ち運べない。
- プロンプト共有は文脈を失いやすく、顧客情報・秘密・著作権上の問題も混ざる。
- 良いエージェントの能力は、実行数ではなく、特定の制約下での品質・速度・費用・再現性で決まるが、比較可能な実績になっていない。
- 再利用者は、品質が不明なテンプレートやプロンプトを購入して失敗する。

## 3. MVP outcome

AI 支援の Web 制作で、制作者が一件の成功した案件から Capsule を作成・公開し、別の利用者が安全に実行して、品質評価の閾値を満たした場合だけ利用料を払えること。

### Success metrics

- 20 人の初期制作者のうち 50% 以上が 1 個以上の Capsule を公開する。
- Capsule 実行の 60% 以上が定義済み評価を完了する。
- 再利用者の 30% 以上が、同種の手作業フローより時短したと回答する。
- 生プロンプト、顧客の個人情報、API キーが公開メタデータまたは台帳に一件も残らない。

## 4. Target users

| User | Job to be done | MVP value |
|---|---|---|
| Maker | AI で Web サイトを納品する | 成功した仕事の型を、秘密を漏らさず収益化する |
| Reuser | 品質が読める AI ワークフローを使う | 実績と評価に基づく Capsule を成果連動で使う |
| Reviewer | Capsule の品質を評価する | 評価の対価を得て、信頼できる市場を育てる |
| Client | 制作物を発注・受領する | 納品品質と来歴を確認する（MVP では任意） |

## 5. Core concepts

### Execution Trace

一回の仕事における、AI 呼び出し、ツール呼び出し、編集、評価、コスト、時間の時系列。生プロンプト・生出力・顧客データは `Private Trace Vault` にのみ暗号化して置く。

### Proof Receipt

Trace から生成する、秘密を含まない実行証明。入力条件のカテゴリ、使用ツール、評価値、費用帯、所要時間帯、Capsule バージョン、検証者署名を含む。公開前に Maker が必ず確認する。

### Skill Capsule

再利用可能な「目的、前提条件、許可ツール、実行手順、評価テスト、制約、ライセンス」を一つにした資産。必ずしもプロンプトを含めない。必要な秘密コンテキストは実行者の端末内でのみ解決する。

### Capability Score

Capsule または Agent が、特定条件下で再現した品質、コスト、速度、失敗率を示す説明可能なスコア。単一の総合点は MVP で表示しない。

## 6. MVP user journeys

### A. Maker: 成功した仕事を Capsule にする

1. メールまたはパスキーでログインする。ウォレット表示は求めない。
2. SDK / ブラウザ拡張を使って、Web 制作作業を記録する。
3. 作業後、AI が Trace から Capsule 草案と Proof Receipt 草案を生成する。
4. Maker は、公開内容、ライセンス、価格、評価条件をレビューし、削除・修正する。
5. PII / 秘密検査に通過すると Capsule が公開され、Receipt のコミットメントだけが台帳に記録される。

### B. Reuser: Capsule を実行して使う

1. 目的、使用ツール、実績、価格、評価条件で Capsule を検索する。
2. 実行前に、必要な入力と「外部へ送られないデータ」を確認する。
3. 利用料を一時エスクローし、自分の環境で Capsule を実行する。
4. 自動テストと本人確認を完了する。
5. 評価条件を満たせば著者へ分配、満たさなければ返金または異議申立てに進む。

### C. Reviewer: 品質を検証する

1. 匿名化された評価パッケージを受領する。
2. 定義済みルーブリックで評価し、署名付き判定を提出する。
3. 一致判定または異議解決時に報酬を受け取る。

## 7. Functional requirements

### Account and consent

- FR-01: メール + パスキーでアカウントを作成できる。
- FR-02: 埋め込みウォレットとガス代は裏側で管理し、公開鍵以外をユーザーへ要求しない。
- FR-03: Trace 取得前、Capsule 公開前、利用前に、別々の明示同意を取得する。
- FR-04: ユーザーは公開済み Capsule を非公開化できる。既に成立した利用・分配の台帳記録は消さない。

### Trace and privacy

- FR-10: SDK はモデル呼び出し、ツール呼び出し、費用、時間、評価イベントを記録できる。
- FR-11: 生プロンプト、生成物、添付ファイルは初期設定で端末外へ送信しない。
- FR-12: 送信可能な情報は、ローカルの PII / secret scanner とユーザー承認を通す。
- FR-13: Receipt は、salt を伴うコミットメントを使い、短いプロンプトを推測可能な hash として公開しない。

### Capsule

- FR-20: Capsule は目的、入力スキーマ、出力スキーマ、手順、ツール要件、評価、禁止事項、価格、版を持つ。
- FR-21: Maker は生成された Capsule の任意の節を編集・削除してから公開できる。
- FR-22: Capsule はバージョン管理され、実行は必ず特定版を指す。
- FR-23: Capsule は「コピー販売」ではなく、実行ごとの利用許諾として提供する。

### Evaluation and settlement

- FR-30: Web 制作 MVP は Lighthouse、リンク切れ、レスポンシブ、指定コンテンツ、手動レビューを評価器として使える。
- FR-31: 評価結果は実行 Receipt に署名して保存する。
- FR-32: 決済前に利用料、プラットフォーム料、評価者報酬、著者取り分を明示する。
- FR-33: MVP では利用料の 80% を Capsule 著者、10% を Reviewer pool、10% をプラットフォームへ配分する。設定は管理画面では変更不可とする。
- FR-34: 72 時間の異議申立て期間を設ける。未解決時のエスクロー解放は行わない。

### Reputation and discovery

- FR-40: Capsule ごとに、実行回数、完了率、評価の内訳、費用帯、時間帯、直近版を表示する。
- FR-41: スコアの算出根拠とサンプル数を表示し、ブラックボックスな総合ランキングを避ける。
- FR-42: 評価を買う、自己実行で水増しする、複数アカウントで反復する行為を検知・保留できる。

## 8. Explicit non-goals

- 売買可能なトークン、投資リターン、利回りの提供
- 個人・エージェントへの信用供与
- 公開プロンプトの永久保存または再販売
- 任意領域の品質を自動で真と判定すること
- 企業・自治体等のオフライン成果を MVP で扱うこと

## 9. Trust and safety rules

- 生プロンプト、API キー、顧客データ、未公開ソースコードをオンチェーンまたは公開ストレージへ置かない。
- 著作権・利用規約に反する入力データの再配布を許可しない。
- Capsule は、再利用者のモデルアカウント、ツール契約、顧客データの責任を引き受けない。
- 収益や将来利益を約束する表現を UI・規約・マーケティングで用いない。

## 10. Open questions

1. 初期決済は法定通貨、カード、ステーブルコインのどれにするか。
2. Reviewer を人にする範囲と、評価器を自動化する範囲はどこか。
3. Capsule の秘密部分を、再利用者の端末内で安全に実行する方法をどのモデル提供者まで対応するか。
4. 複数の Trace / 著者が一つの Capsule に寄与する場合の分配ルールをいつ導入するか。
