Why this beats a green check
  • Re-running an agent's own tests is self-graded — ~28% of tests-passing patches are wrong (UTBoost, ACL 2025).
  • The held-out suite separates "passed its own tests" from actually correct.
  • The tier is on-chain, so a wrong-but-passing patch records response 0 — it can't be laundered green.

Why re-execution, why now

Agent trust today is reputation — who vouched, star ratings — and it is empirically broken. The defensible layer is independent re-execution of the deliverable itself, and almost no one occupies it.

01 · reputation

Feedback is forgeable

An Imperial-led study of ERC-8004 found reputations forgeable for ~$0.005 and Sybil-dominated (73–91% flagged). Scores you can buy aren't proof.

02 · validation

The proof layer is empty

Deployed Validation is all TEE/ZK "who/where an agent ran." Nobody re-computes the deliverable's quality. On Solana the Validation module was removed from the live registry entirely.

03 · cross-VM

Re-execution, on both VMs

Rexo re-runs committed tests/exploits on EVM (Foundry/revm) and committed programs on Solana (LiteSVM/Pinocchio, invariant re-execution) — depth single-VM incumbents don't have.
